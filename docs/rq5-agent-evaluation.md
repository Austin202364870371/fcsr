# RQ5：除任务完成率外，如何量化 Agent 的任务执行质量？

**状态：研究设计；端到端指标尚待环境接入。**

## 问题与原则

任务成功率是主终点，但不能解释成功来自检索、规划还是更高成本的重试。RQ5 建立分层指标，既不把代理指标冒充为任务完成，也能定位检索与 Agent 执行环节。

所有指标按任务保存原始 trace 和完整分母；超时、解析失败和预算耗尽不可删除。

## 指标层级

| 层级 | 指标 |
| --- | --- |
| Outcome | verifier reward、任务成功率、首次尝试成功率 |
| Retrieval | Recall@K、nDCG@K、MRR、FullCoverage |
| Selection | GT 覆盖、无关 Skill 数、依赖违例率 |
| Planning | 有效计划率、计划深度、计划-执行偏离、重规划次数 |
| Reflection | 失败后修复率、重复失败率、错误分类一致性 |
| Efficiency | token、模型/工具调用、步骤、墙钟时间、峰值上下文长度 |
| Reliability | 解析失败、超时、预算耗尽和可复现率 |

## 统一记录与比较规则

每任务记录运行 ID、代码/配置/manifest 版本、种子、模型、Skill pool 与 Top-K、计划/反思版本、每步动作观察、verifier、终止原因和成本。模型可见 trace 必须与私有 GT、oracle、verifier 内部数据分离。

每份报告同时输出任务级 JSONL 和汇总 JSON，支持按 single/multi-skill、任务类型、候选池和失败类别切分。报告置信区间或配对重采样区间及完整分母。

RQ1 的主指标是检索质量；后续 Agent 实验的主指标是同一 verifier 下的成功率。成功率相近时才比较成功任务成本，同时保留全部任务成本。改变模型、候选、步骤或重试预算即构成新条件。

## 当前可用与下一步

当前仓库已经提供 RQ1 的检索指标。未来接入端到端执行与 verifier 时，应先定义共享 trace schema 和报告写入器，让后续 Agent 实验使用同一测量契约。

## 与其他 RQ 的关系

RQ5 不是额外功能，而是检索与后续 Agent 实验的共同测量契约。任何新模块进入实验主线前，必须说明改变的主/辅助指标及保持不变的条件。
